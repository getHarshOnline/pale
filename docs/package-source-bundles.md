# Package source bundles

Use a source bundle when another checkout or host needs Pale's Package methods. The archive contains the requested Packages, their pinned dependencies, and the licences and notices that identify where the files came from.

## Inventory a detached Package source set

From the checkout, run `python3 tools/package_corpus_inventory.py /absolute/source-root` to list each Package's declared licence, source file digests and pinned dependencies. This uses Pale's Rust reader through the CLI, so declaration and link checks agree with compilation. Creating the inventory needs the checkout's Rust toolchain and Python 3.11 or newer. The inventory includes the corpus notices and the upstream licences. It fails on an undeclared Package file, missing notices or a dependency pin it cannot resolve. The bundle does not include Pale’s runtime.

For a bundle of design methods, pass `--package pale.design` to include that Package and the dependencies in its manifests. Repeat `--package` to request more Packages, or omit it to inventory all Package sources. These flags choose files for the archive. The project, operation, host, grants and runtime profile are outside that choice.

`--paths` prints relative paths within the source root. It includes the notices, upstream licences and verification tools, and writes no files. From the source repository, create a fresh directory for the outputs and pass the path list to `tar`.

```sh
mkdir /absolute/fresh
python3 tools/package_corpus_inventory.py . --package pale.design > /absolute/fresh/inventory.json
python3 tools/package_corpus_inventory.py . --package pale.design --paths > /absolute/fresh/paths.txt
COPYFILE_DISABLE=1 tar -cf /absolute/fresh/methods.tar -T /absolute/fresh/paths.txt
```

Compare `tar -tf /absolute/fresh/methods.tar` with `/absolute/fresh/paths.txt`. Use the verbose listing to confirm every member is a regular file. Reject symlinks, AppleDouble metadata and generated bytecode. On macOS, `COPYFILE_DISABLE=1` suppresses that metadata, and the archive listing confirms which files are present.

Extract into a new empty directory. Run `python3 /absolute/extracted/tools/package_corpus_inventory.py /absolute/extracted --verify /absolute/fresh/inventory.json`. This detached check needs only Python: it checks the exact files and digests against the saved inventory without reinterpreting Package declarations. A changed or extra Package file fails verification. Deliver the inventory alongside the archive and compare it with the sender's original. Keep any host-written instructions and inspection records with the delivery, clearly identified apart from the upstream source files. Record the archive digest separately from the source revision so you can identify both what you delivered and where it came from. Change the maintained sources upstream, then regenerate the bundle.

Before distributing the archive, review its included licences. In the receiving host, check that the requested methods load and their required links lead to the bundled guidance. You can read the methods without a running Pale service or a private checkout. Run `python3 -m unittest discover -s tools/tests -p test_package_corpus_inventory.py` to test whether the inventory detects missing or altered sources.

### Verify current Package composition

After checking the extracted files, point a disposable workspace's machine binding at their root and run `distribution-info` to calculate the compiler's release digests. Use the distribution lock for that source to validate the profiles, then review a plan and inspect the files it writes to a disposable target. The archive inventory identifies the copied files. The lock tells the compiler which release inputs to use. Record build and licence checks against the files that actually ship.

Run `cargo test --locked --offline -p pale-application --test packages` to check how Pale reads and accepts Package sources. Run `cargo test --locked --offline -p pale-application --test compile current_corpus` to check the current authored workflows.

The second test builds disposable fixtures from the maintained sources and checks what Pale writes for Codex and Claude. Required guidance appears once, optional guidance stays discoverable, and links from skills, agents, startup and internal-operation files reach their intended resources. Pale refuses a Publication operation when its provider is missing. For rejected link destinations, diagnostics report a hash of the destination without copying the raw source text. These tests need no previously built executable. They check compiler and renderer behavior. To establish host invocation, agent judgment or publication quality, inspect those outcomes separately.

When changing resource bodies, follow the [body-link authoring contract](package-authoring.md#keep-body-links-aligned-with-typed-references).
