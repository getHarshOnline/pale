# Form roles and components from recurring meanings

## Form from semantics

Collect accepted brand direction, representative flows and states, existing components and style values, accessibility constraints, and recurring product concepts. Separate a deliberate convention from accidental repetition.

Define semantic purposes before implementation values: critical action, subdued text, raised surface, or warning state before a particular color, size, or token name. Promote a component only when its content, state, interaction, and accessibility contract recur. Document legitimate variation; reuse must not flatten differences that matter to the task.

Read the original brief, corrections, selected references and their declared roles before deriving rules. A reference may establish identity, a particular interaction, construction technique or an exact reconstruction target. Its presence in a folder does not establish that it was studied or applied. Keep the intended qualities with the decisions they informed. An approved repair retains settled direction; a new design can explore alternatives where they answer the actual brief.

Separate the shared method from the project’s identity. Material, type voice, geometry, light, density and temporal character can distinguish related surfaces while focus, dismissal, keyboard behavior and truthful state retain their shared contracts. A palette swap alone does not establish a different identity. Conversely, useful shared construction need not be made different merely to produce a novelty score.

## Worked example

An error message, raised card and command label need different roles. A bright accent already used by the header can still be an independent choice from the warning color. Define the meanings, decide which states recur and draw the component in the real flow. Two brands can keep the same keyboard and dismissal contract while using different material, scale and light. Ask which reference determines each of those choices.
