# Plan work that can continue across sessions

Use this method when authorised work crosses sessions, owners or required reviews and cannot depend on someone remembering the conversation. Divide it into results that can be checked separately, then order them by what each needs from the others.

## Start with the request and current sources

Read the intended outcome and exclusions, the current files and repository revision, limits on ownership and changes, time and cost budgets, acceptable risk, and the checks that will establish completion. Carry permissions already given with the plan.

## Give each part a result and a restart point

For each independently useful result, identify the inputs, permitted changes, expected artifact, owner, acceptance check, dependencies and when control returns. Order parts by the outputs they need, rather than by an assumed calendar. Work can run in parallel when write scopes are separate and neither part waits for evidence from the other.

Where review is required, the next part uses the named, accepted version. A claim that the previous task finished is insufficient. If evidence changes how work should be divided, update the affected downstream steps in the existing plan, keeping the original decision and the reason for changing it.

## Return a usable plan

Put the ordered work, handoffs, risks and open questions in the task's existing plan or reply. Use a dependency graph when it helps. Finish dividing when each part has one coherent result, one owner and a check a fresh worker can run without hidden context. The plan coordinates work; starting it or accepting its result still uses the owner's actual permissions and decisions.
