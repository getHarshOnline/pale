# Check actions in their intended page slots

Associate the owner's placement decision with the publication, page or family, slot, action and destination. A shared navigation or footer link establishes a route. Making it an inline prompt, reading-rail action or closing action needs its own placement decision. Keep exceptions at their approved scope. Before changing a slot, trace its selection, template inheritance and component defaults.

In the output under review, compare action, slot and destination independently. Test a page requiring the prominent action, one retaining ordinary navigation while excluding the prompt, and each approved exception. Check neighbouring pages sharing the template or link for unintended effects. Preserve route behaviour, including address mapping and the difference between opening a message and starting a booking flow.

In the review, distinguish required, excluded and unresolved placements. A page family absent from output has not been observed rendering. Identify the output inventory and governing decisions. Use the browser for prominence or interaction claims that generated structure alone cannot establish.

## Worked example

Two page families share a booking route in navigation, but only service pages should show an inline prompt. Inspect a service page, a reading page retaining the navigation link and any explicit exception. Compare visible action, position and destination. A link opening email cannot establish a working booking flow.
