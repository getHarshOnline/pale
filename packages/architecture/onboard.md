# Find your way into a codebase

Start with the repository entry and local instructions. Identify the requested change, its actual entry points and callers, and the commands used to build and test it. Follow the components that own its dependencies and read their relevant source.

In the handoff reply, give the next person or session the scope, useful paths, first proposed change and way to check it. Say which observations are stale or still unresolved. Stop once they can begin the task; do not invent an architecture or a command the repository does not establish.

## Before handing off

- [ ] Find the owning repository and real entry for the task.
- [ ] Read the local instructions, build path and affected code.
- [ ] Name a first change and how to check it.
