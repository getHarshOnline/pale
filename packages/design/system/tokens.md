# Resolve a token change through its build

## Resolve a presentation decision

Preserve source meaning, rights, destinations and qualifications first, then access and applicable interaction/runtime contracts. Derive the selected identity and local expression within those boundaries. A runtime's aesthetic preset does not override an accepted brief. A technical limitation is an explicit integration question; it is not authority to quietly remove a required quality.

When two aesthetic readings are both defensible, name the tension and choose from this subject, context and intended effect. Keep that decision local unless it establishes a genuinely reusable contract. An unresolved conflict about meaning, access or shared behavior needs its owning source or decision; hold the dependent change rather than inventing a compromise. This design reasoning does not change the governing instruction or authorization order.

One owner supplies each token value, component recipe and interaction contract. A token name does not freeze a wrong value: correct it at its owner and follow its real consumers. A component recipe describes anatomy and styling; it is distinct from a publishing engine's build recipe. Author a new shared primitive only for a recurring semantic need, preserving justified local exceptions.

For token changes, resolve the actual modifier order and defaults rather than assuming a mode or output. Alias a decision only when it should inherit future changes; numeric equality does not establish that relationship. Check type, unit, alias chain and relevant structured metadata in the built projection. A length, unitless coefficient and controller time can need different conversions. Preserve each consumer's numeric contract and convert once. Generated output remains derived; remove stale members only in an owned output location and verify the rebuilt consumer path.

## Worked example

A hover value and a focus value happen to match. Give them different names because the later focus change should reach a different set of consumers. Check how base, brand and mode resolve for the actual target. Inspect both built values, then the component’s computed result. Keep milliseconds, lengths and unitless coefficients distinct when exporting them for CSS or a controller.
