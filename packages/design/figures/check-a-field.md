# Exercise a figure in the page that uses it

## Inspect the consuming region

Reach the real page by its path and exercise the affected inputs and fallbacks. Check the original failing case, the supported preference changes, mounting, leaving and returning, and the relevant lost/restored capability. Observe performance alongside composition and actual semantic output. Flashing and rapid luminance changes need the applicable safety criteria; a general preference setting does not establish that they are safe.

Separate the things you observed: source checks, an isolated specimen, rendering in the consuming page, input behavior, creative judgment and owner approval are separate. A successful shader compilation cannot establish useful explanation, accessibility or outcome. Correct the owning shared source and recheck its actual consumers; avoid an expanding checklist that goes beyond the actual change.

| Relevant check | What establishes the result |
| --- | --- |
| Purpose and reuse | Name the role in this page; reuse keeps the intended identity or relation instead of repeating a false claim. |
| Removal | Every fact and access path survives; the selected expressive contribution is perceptible when restored. |
| Payload | Compare values, units, dates, source, status and destinations with their owner; inspect what apparent thickness, scale or order implies. |
| Spatial allowance | The actual crop and overflow fit the region's selected role and the adopting system's permissions. |
| Still and reduced form | Each is deliberately composed, carries the same relationship and avoids an arbitrary paused frame. Change preferences during use as well as before mount. |
| Dark and narrow forms | Ground, light, crop and controls remain composed beside the surrounding page; an inversion or shrink alone is insufficient. |
| Capability failure | Block script or graphics where those fallbacks are promised; also exercise initialization failure and context restoration. The still and semantic alternative remain useful. |
| Input and clocks | A bound response repeats at the same settled input with any separate clock fixed; a played response reaches its intended rest. Test reversal, leaving, cancellation and zone borders. |
| Access and disclosure | Keyboard and supported touch paths reach meaningful states and real links; informative alternatives survive mount. Keep useful attribution and qualifications, with internal production notes at their owner. |
| Cost and lifecycle | Measure the busiest view, mounting and first start; observe offscreen and hidden suspension, reentry and resource cleanup. |

Mark each relevant result passed, failed, blocked or not run in the existing review. A capture must be inspected to support its visual claim. Record rapid luminance changes and assess the applicable flash criterion through [Keep the task available when motion changes](../access/motion-accessibility.md); an informal frame-step or reduced-motion preference alone cannot certify safety.

## Worked example

Open the real page and read its fallback before the figure mounts. Drag both directions, navigate by keyboard, change motion preference, then scroll away and back. Compare the visible state, labels and memory use. Force the supported failure in a test browser. Record which run checked the restored drawing, which checked the access path and what still needs a person to assess its design.
