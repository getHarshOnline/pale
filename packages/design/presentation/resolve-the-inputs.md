# Resolve each input from the source that owns it

## Resolve each input from its own owner

Identify the selected source, object identity, intended audience task and form. Keep product truth, editorial choice, interaction state, user preferences, available capabilities and visual treatment distinct. A theme does not decide who owns the work. Screen width does not decide which claims are true. A capability being installed does not make it available, authorized or selected for this task. A title or URL resemblance does not establish an entity relation.

Use the semantic model and established components. The recurring anatomy of an object can support a row, inline reference, card, citation, search result, embed or detailed page without becoming several independently maintained facts. Share the semantic contract and correct its actual consumers. One universal macro, fixed ontology or token-resolution function is not required. A film, browser document and interactive application have different implementation and fallback contracts; preserve the meaning through their appropriate forms.

Choose the dominant task before arranging the page: orientation, sustained reading, applying an exact instruction, comparison, choosing among records or making a decision. Supporting regions need not take over the whole page. A research document does not become a sales page because it has a contact path. Map tasks to the project's actual page-family mechanism only at its native owner. Do not import another project's mode names, family defaults, attributes, amplitude ceilings or override rules. A requested exception does not silently remap unrelated content when the engine lacks a sufficiently narrow selector.

## Resolve presentation without mixing up its inputs

Take the source identity and target identity from their respective objects. Derive where a link leads from those identities and routes. The link's editorial relationship comes from the content. A page can link to a different site and still describe a related work, and two pages on the same site can point to unrelated things. In either case the target supplies the same underlying facts.

The component supplies the form and prominence, while the person and system supply the interaction state, preferences and available capabilities. Choose these inputs independently. A preview borrows the target's identity only to the degree its placement needs it. A device that cannot draw an effect still gets the same values, qualifications and useful destination.

Derive semantic roles before component appearance. Primitives can feed roles, and an identity can supply a different role value without changing what that role means. A local component can use its own named slots for decisions specific to that component. Compose semantic document and reading presentation first, then interactions, motion and visual computation where they help. An enhancement should never become the only place a required fact or action survives.

Trace a disputed treatment through the actual layers: primitive or source value, semantic role, identity or mode selection, relationship and task adjustments, then the component's slot. Name the layer that owns the change before editing it. A repeated design choice may need a shared role; a scene coordinate, normalized progress value or algorithm constant need not become a global token. When the system has a resolver, inspect its selected contexts and resolution order rather than assuming that an override in one stylesheet reaches every consumer.

For a progressively enhanced publication, check each addition over a usable preceding form: document, reading styles, interaction, motion, then optional visual computation. Remove a later capability and inspect what remains. Keep this test scoped to the delivery contract; a computation-dependent application may correctly expose an unavailable operation, and a rendered film has its own authored frame and host-player contracts.

## Worked example

A report links to a project page. Its author and date come from the report. The project page’s title and destination come from the project. Style the relation in the current page without silently changing its type or importing the target page’s claims into the report. A preview can carry the project’s label and link while leaving the real target in control of its own details.
