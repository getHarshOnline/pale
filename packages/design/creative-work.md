# Start from the creative result the task needs

Establish the audience, medium, sources, constraints and acceptance criteria before making or diagnosing the work. Use the model to interpret the sources and exercise taste; use the capabilities supplied by the project to retrieve, save, execute or produce media. Keep each source's origin clear. Distinguish a proposal, a saved artifact, a rendered result and a checked result. In the reply, identify the actual artifact, the checks completed and anything that remains unavailable or untested.

Reuse the current request, the owner's sources, settled direction and existing brief. Ask only about gaps that change the work. Keep original words, later corrections, interpretations and working assumptions distinguishable. A focused repair within an accepted direction can proceed without restarting boards, identity selection or production setup. A project-wide inquiry needs more preparation than one page correction.

Choose the production route from the intended result, the role of each source and the control the work needs. Authored construction and supplied media may already provide everything needed. If the task requires a particular tool or production method, use an authorized equivalent only when it preserves the requested result. An unavailable optional engine holds up only work that needs it. Before running a production tool, check the relevant setup; distinguish declared configuration, a process that responds and a completed useful run.

Continue within existing authorization. When a choice remains with the owner, finish the concrete comparison first, show candidates under comparable conditions and ask the question their difference answers. Include material cost, rights, tradeoffs and the next action that depends on the choice. Ordinary reversible work needs no extra approval ritual or stage log. Silence supplies no new permission and leaves existing permission in place.

For a necessary handoff, name the action, why it is needed now, exact steps, cost and its current source, what must come back, and what can proceed meanwhile. Give a recommendation tied to the brief and an honest limitation for each candidate. A default belongs only where the agent has authority to choose it. Batch decisions that arise together; do not ask for the same approval again on resume. If candidates differ in so many unrelated ways that the choice is unclear, make the next comparison answer the unresolved question. Coordinated changes can still form one explained creative direction.

On resume, compare the current request and source revisions with the application's state, pending jobs and existing run records before starting another job. A saved stage may lag a completed run. Reopen only decisions and observations affected by a changed premise, retaining unaffected approval and historical results. Put enduring decisions in the project's existing brief or records and use its configured tools; keep assets with their owner instead of making another archive.

## Before handing off

- [ ] Does the result answer the current brief and preserve the settled direction?
- [ ] Are the source roles, production route and existing permissions clear?
- [ ] Does the reply identify the actual artifact, observed checks and work still unresolved?
