# Verify the implementation and inspect its actual output

Identify the exact revision and affected surfaces. Reproduce prior failures first and inspect the consumers the change can affect. Use an earlier failure or a known-bad control where it is needed to establish that an important check detects the defect. Run the implementation’s own tests or viewer, and obtain fresh captures, interaction results and measurements. Builder captures can help locate a problem. Keep technical checks, rendered observations and design judgment distinct.

If this reviewer cannot run a check, request that specific check through the owner’s permitted route. Attribute the returned result to its actual runner in the existing review and leave unavailable checks open.

For a film, identify the source revision and exact encode. Check playback, seeking, transitions, applicable sound and media access. Inspect controls, fallback and preferences in the embedding surface when the claim concerns that surface. State whether the result came from tool setup, a disposable fixture or the actual target.

Return the revision, checks run, capture paths, warnings and unresolved conditions in the project’s existing review or reply. Supply the verified captures and what each shows to the critic when design judgment is also required.

## Before handing off

- [ ] Do the observations identify the actual revision, surfaces and conditions checked?
- [ ] Were failures reproduced and important checks shown to detect their defects where needed?
- [ ] Are captures, runner attribution and unavailable checks clear in the existing review?
