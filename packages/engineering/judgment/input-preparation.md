# Prepare an input without losing what matters

Use this before resizing, re-encoding, repacking or converting an input for a consumer. Establish the consumer, source types it accepts, original identity, proposed transformation and qualities the task needs preserved. Check whether the source is permitted before deciding whether optional preparation is useful. Converting it cannot make a rejected source type or prohibited use acceptable.

## Keep the original and the transformed copy distinct

Retain the original under its owner's retention and access rules. Give the transformed copy its own identity and connect it to the original, tool version and effective settings. Check the emitted bytes, media type, dimensions or structure, and which copy the consumer actually receives. Test the qualities the task depends on with representative pairs: smaller bytes, successful decoding or a matching filename alone cannot establish preserved text, fine detail or page meaning.

When integrity depends on original bytes, keep them intact and use a transformed copy only through a separately permitted route. A marker scan can conservatively bypass conversion. State what it scans and what remains uncertain: no marker found leaves signature validity, intact signed bytes and permission to rewrite unestablished. Use the owner's actual signature verifier for those checks.

## Limit optional work and keep fallback safe

Use the owner's source classes, size thresholds and resource limits to decide whether preparation is worth attempting. Perform the acceptance and bypass checks before loading an optional converter. Compare its result with the original; keep the original when the conversion brings no benefit under the task's requirements.

A decode, parse or conversion error may fall back to the original only if that original is still permitted and useful. Fallback must retain source rejection, privacy limits and cancellation. Follow cancellation through preparation, encoding, submission and late results. Check it before dispatch and at interruptible expensive steps. If a helper catches an error and returns the original, its caller must still stop cancelled work. Establish local cancellation, remote completion and provider usage separately.

## Check the proposed conversion

Exercise applicable source types, work below the threshold, a conversion that gives no benefit, malformed input, converter failure, an original whose integrity matters and cancellation. Check the original identity on bypass and fallback, and verify that unnecessary dependencies were never invoked. Compare representative original and transformed inputs using the exact consumer and the qualities the task requires.

A stub converter can check routing and fallback. Use the pinned real converter and its emitted output to assess the actual conversion. Measure transfer size, encoding and decoding time, consumer quality, resource use and provider usage separately where those are claimed. A reduction in bytes alone cannot establish token savings, legibility or response time.

In the reply or existing conversion report, give the cases covered, observed outputs and remaining quality, integrity or usage checks. The owning system chooses converters, thresholds, storage, execution and acceptance.
