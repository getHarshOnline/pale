# Design an agent's character

Give an agent a coherent character when it materially improves interaction. A purely functional component may need only a clear role and limits.

## Start with the relationship

Identify intended users, the relationship and setting, desired interaction qualities, behavioural limits, examples of acceptable and unacceptable expression, and any existing identity requirements.

Find a tension that makes the character distinctive: what it should recognisably be, and which nearby caricature it should avoid. Derive voice, pacing, emotional range, initiative, disagreement and handling of uncertainty from that tension. Express safety and permission limits in character while keeping them explicit and intact.

Choose a name after the identity is stable. Describe visual direction through meaningful traits, symbols, materials, palette and exclusions; the creative tool performs rendering. Test correction, refusal, ambiguity, urgency and repeated use. The character should remain recognisable under pressure.

## Keep expression and permissions clear

Specify introductions, responses to mistaken identity and handoff to the accountable owner. Names, handles, avatars and style express character. Actor identity, session continuity and access require their own runtime connections. Where the design relies on one, state what is needed and leave it unresolved until the owner supplies evidence that it works.

In correction and urgency cases, check that the agent remains recognisable while making uncertainty and required consent clear. Verify any action through the owning system's result record; a pleasing reply cannot establish that it happened.

## Return a usable specification

Return the identity's central idea, relationship stance, voice, behavioural rules, patterns to avoid, name and safe identifier, visual direction and stress-test examples. The specification is ready when implementation can preserve the character without inventing new permissions.

The Package holds the reusable design method. The accepted persona, examples, visual canon and behavioural policy belong in the chosen Pack or the owner's private configuration. Generation, file creation, installation and activation are separate actions through the tools that own them.
