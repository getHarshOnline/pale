# Make a cut that shows what changed

Put the audience and lead claim in the existing edit plan. Show the outcome early and use a recognizable object or workflow across the beats when it helps. For each capability the overview needs, show its starting state, meaningful action and visible consequence. If a viewer could explain it as a generic click, search or page change, find the response that makes this subject distinct. A punch-in can isolate the input, a match can preserve identity, and a pullback can show the reach of the result. Choose each move for what it lets the viewer understand.

When one action produces distinct native outputs, show a readable crop of each output's actual type, structure or behaviour before its complete view. When the same object changes reading form, retain its identity and the smallest verbatim detail that distinguishes the new form. If the same labels name the inputs and outputs, compare keeping the labels in place while the actual result changes underneath. Swapping labels or showing only the aftermath can hide the action the film needs to explain.

When a tool opens evidence about the subject, keep the subject legible as context and give the opened evidence the active focus. If an input has left the native interface, carry its meaning in editorial type that the viewer can distinguish from controls still in use. Choose the framing for that subject and change: a source preset's top-centred presenter is not the default for a product film. Do not reuse a page input controller as the film's timeline controller.

Check the smallest intended fitted picture. Give each beat a primary viewing task and count required reads inside the recording as well as outside it. Hold the result long enough to register. Let runtime follow the actions, holds and joins. A timing limit from one social cut applies to that cut. If the available time is tight, agree which content to leave out and give the remaining actions room. Check a comparison at fixed timing when that isolates the change. Then revisit the actual master timing and watch the affected joins together.

Show a short animatic at its intended pace to someone who has not heard the editor's explanation. Keep functional text such as the actual word that changes in a text editor. Cover explanatory copy first. Ask what happened, what produced the response, and where they saw it. If functional text carries the explanation, a second pass briefly covering it can show what the action and composition contribute. Then restore the full copy. Compare the retelling against the original brief, corrections and references.

Keep distinct what the viewer saw, inferred or learned from a label. If a claim depends on a handoff, show what passes between steps. A match across separate captures can show the same object. It cannot establish a transfer the captures did not record. When repairing one beat, recheck its neighboring holds and the first readable incoming state. Reuse an earlier whole-cut comparison when those relations and timing still hold. Watch the revised export before settling the edit.

Where a useful product change is hidden, show its first observable consequence from the actual product. Compare the opening, central change and payoff at the intended pace. A technique can work in each shot and make the joined film feel like one held pose. Test a change in framing, relationship or energy that gives the viewer a reason to move from one beat to the next.

Use [Plan a shot from both ends](../films/frame-a-shot.md) to connect treatment, the simpler alternative considered, depth and reading load with the existing edit plan. For footage of the actual interface, [Record a real interface demonstration](record-a-demo.md) covers discovery, rehearsal and capture.

## Worked example

An overview shows a report created from a filtered data set. The first cut shows a filter click, a spinner and an export button. A viewer describes a generic download. Show the narrowed results and the changed total before opening the report. Hold on the corresponding range in the report. If these are separate runs, match the documented data range and show the join without animating a file passing between tools. Compare the new sequence at the target size with the original cut.
