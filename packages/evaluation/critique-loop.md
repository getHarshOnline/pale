# Review successive versions of a candidate

Give the evaluator the governing inputs and an exact, fixed candidate. Keep the generator's conclusion and desired verdict separate from that evidence. If no independent evaluator is available through an authorised route, report that limit. Self-review can find defects, but it cannot meet a requirement for independent review.

For each criterion that can block acceptance, give a pass, fail or unverified result and point to the evidence. An unverified requirement remains open. Return the candidate reviewed, each exact finding and supporting observation, who owns the repair, and what evidence would settle the question. A proposed change is separate from the next candidate submitted for review. Track what happened to findings across revisions while keeping the same rubric.

Accept when the agreed blocking criteria are satisfied. Revise when there is a specific repair that addresses the cause and another round can test it. Stop or escalate when a premise remains unsupported, authority is missing, the budget is exhausted or the brief must change. The engine or project tools perform any state change, artifact edit or recording of the result.

## Before handing off

- [ ] Keep the candidate, rubric and comparison conditions stable.
- [ ] Use findings to test a named revision.
- [ ] Stop when the check no longer distinguishes useful progress.
