# Verify recovered references from their original base

<a id="check"></a>

Identify the referring revision, original member path and base namespace, and saved archive or source version. Moving a document can preserve its text while changing relative links. Recover its original base from the owner's records and resolve only within permitted members. For cross-namespace links, use that namespace's separately pinned inventory and mapping. A matching basename does not identify the target.

Verify the file or member before its exact fragment or declaration. Apply the actual reader's identifier rules, including supported explicit anchors, punctuation, duplicate headings and encoded fragments. A source heading, rendered ID and observed navigation establish different things. For a rendered reading route, inspect output or use the reader's resolver. Confirm the intended section and revision opens despite another destination with the same label.

Keep original bytes and locators. Put current navigation corrections or alternate owner routes in an existing maintained index or patch. For a recovered patch chain, verify the base and patch order, then inspect the restored document and target section. State which historical defects remain. Test a correct file with the wrong fragment, relocated base and unavailable or ambiguous target. Report verified paths, versions and reader modes alongside gaps.

## Before handing off

- [ ] Resolve the reference from the original document and its base.
- [ ] Check the target identity when the same path exists elsewhere.
- [ ] Compare the recovered target and the original relationship.
